Best AI Agent Framework 2026: A Live-Data Scorecard

Twelve agent projects, measured on 19 November 2026 against a rubric written before the results. Stars and downloads rank them differently, and one top-three project is archived.

Short answer: on 19 November 2026, six of the twelve projects I measured passed a maintenance-and-adoption rubric I wrote before reading the results: LangGraph, OpenAI Agents SDK, Google ADK, PydanticAI, CrewAI and OpenClaw. AutoGen's own README says it is archived and unmaintained, and the original Letta repo has been retired in favour of Letta Code. GitHub stars would have ranked these projects differently, and wrongly, for a new-project decision.

Updated November 2026. I ran every number on this page on 19 November 2026 between 13:01 and 13:05 UTC, from one server, with Python 3.12.3 and the unauthenticated GitHub API. The scripts are reproduced in section 11, so you can rerun them and get today's numbers. I did not build the same task in each framework, so this page scores maintenance and adoption, not how pleasant any of them is to write.

1. The decision

The question behind "best AI agent framework" is rarely a features question. A team picks a framework, builds three or four months of work on top of it, and then finds that the project stopped shipping, or changed its architecture, or never had many users outside its launch week. Migrating off a framework mid-project costs far more than a week of comparison up front.

So I wanted a comparison that answers a narrower question with data anyone can check: if I start a new project on this framework today, what is the evidence that it will still be maintained and used in a year? That is the part of the decision a marketing page cannot answer, and it is the part where GitHub stars are most often misused.

This guide is for an architect or technical founder choosing a framework, or deciding whether to migrate off one. It supports the work I describe on my AI agents page, where I help teams pick and build agent systems. It does not tell you which framework has the nicest API. That needs a build, and I did not do one.

2. How I measured it, and what went wrong

I picked twelve projects: nine agent libraries or SDKs that come up in framework comparisons (LangGraph, CrewAI, AutoGen, AG2, PydanticAI, OpenAI Agents SDK, smolagents, Google ADK, and Letta, whose current code lives in a successor repository called Letta Code, so it gets two rows), plus Microsoft Agent Framework, which AutoGen's README now points new users to, and two open-source agent products that people constantly compare to them, Hermes Agent and OpenClaw. Section 7 explains why those last two are a different kind of thing.

For each project my script called three GitHub API endpoints: the repository record (stars, forks, open issues and pull requests, creation and last-push dates, licence), the release list, and the commit list filtered to the last 90 days. The commit count comes from the pagination header: ask for one commit per page, and the number of the last page is the total. For the registry signal it asked pypistats.org for last-month PyPI downloads, or the npm registry for last-month downloads where the project ships on npm.

Four things did not go to plan, and each changed the page.

  • The token was rejected. A GitHub token in my environment returned "Bad credentials", so I ran unauthenticated, which allows 60 requests an hour. That capped the design at three calls per repository and made me skip a star-history check.
  • The first release count was capped. I asked for 30 releases per project and six of them returned a full 30 inside 180 days, so the count was a ceiling and I stopped reporting it.
  • Hermes Agent's newest release was a canary. The newest GitHub release was v0.23.2+canary.20261119T064637Z, a prerelease. I pulled 100 releases, found 49 stable ones among 56 since 12 March 2026, and used the newest stable one, v0.23.2 from 16 November.
  • Microsoft Agent Framework's repository returned 404. Both api.github.com/repos/microsoft/agent-framework and the github.com page returned 404 to my unauthenticated requests, although AutoGen's README and the package's PyPI metadata both link to that address. I could not explain it from here. It might be private, moved or a regional block, and I did not guess. That row is scored from the registry alone and marked "unscored".

I also read four READMEs directly (AutoGen, Letta, Hermes Agent and OpenClaw) from raw.githubusercontent.com, because a project's own statement about its status is evidence that no API field captures. That turned out to matter.

3. The rubric, stated before the results

I wrote these rules before running the analysis, and they are in the script in section 11. They are my judgment, not a standard, and section 9 shows how the verdicts move if you change them.

  • Maintained: a stable release in the last 90 days, and at least 50 commits in the last 90 days, and the project does not describe itself as archived or retired.
  • Used: at least 1,000,000 registry downloads in the last month.
  • Ready: maintained and used.
  • Ready with caveats: maintained but under 1,000,000 downloads, or a release 91 to 365 days old with commits still landing.
  • Not yet, avoid for new projects: documented as archived or retired, or no release in more than 365 days.
  • Unscored: repository metrics unavailable.

Two caveats apply to every verdict below. A verdict is about maintenance and adoption only. And "used" is a registry download count, which includes continuous-integration runs, mirrors and any package that depends on the project. I did not trace dependents, so a download figure shows reach, not the number of teams building on it.

6. What the numbers say

Stars and downloads disagree, and the gap is large. Among the projects where I have both figures, downloads per star run from 7 for AutoGen to 1,351 for LangGraph. That is a 193-fold spread. CrewAI has about 1.35 times LangGraph's stars and about 4 percent of its monthly downloads (2,578,165 against 60,983,685). I do not read that as CrewAI being bad. It may reflect where each package sits in other packages' dependency trees, which I did not trace. I read it as proof that a star count cannot stand in for usage.

The top three by stars would have misled a new-project decision. The three most-starred projects in my set are OpenClaw, Hermes Agent and AutoGen. AutoGen's README states, in a caution box, that the project is archived and that Microsoft is "not providing bug fixes, security fixes, new features, or support". GitHub's own archived flag read false when I queried it, so the README and the API field disagree. I trust the README, which is the maintainer's explicit statement, and the data agrees with it: 3 commits in 90 days and a newest release dated 30 September 2025. The README tells new users to start with Microsoft Agent Framework, and the migration guide it links to returned HTTP 200.

A star count can follow a retired codebase. The original Letta repository has 25,489 stars. Its README now says the current source lives in letta-ai/letta-code and that the retired V1 API server sits on an archive branch. The active repository has 3,875 stars, so the old one carries about 6.6 times the stars of the one being developed. Anyone sorting by stars would find the dead one first.

Open-issue load differs a lot between healthy projects. Open issues and pull requests, as a share of stars, were 1.1 percent for LangGraph, 2.0 percent for CrewAI, 2.1 percent for OpenClaw, 8.6 percent for PydanticAI and 20.4 percent for Hermes Agent. PydanticAI's figure sits next to the busiest commit stream among the libraries (2,910 commits in 90 days), so I read it as a busy project, not a neglected one. I would not read much into the ratio alone. A tracker that is never triaged and a tracker that receives a lot of traffic can produce the same number.

The two biggest projects are also the busiest, and I could not fully reconcile that. GitHub's pagination count gave about 49,000 commits for OpenClaw and about 50,000 for Hermes Agent over 90 days, roughly 550 a day each. I report those as GitHub returned them. I also sampled the 100 most recent commits on each. Hermes Agent's came from 12 distinct authors, two of whom wrote 75 of the 100, and none were bot accounts. OpenClaw's came from 16 authors, the most active of whom wrote 33, with 2 bot-typed commits. A sample of 100 cannot validate a 90-day total, and the commit dates in my Hermes Agent sample did not line up neatly with the 7-day count, which may come down to author dates against committer dates. I did not chase it.

7. Hermes Agent and OpenClaw are a different kind of thing

The two projects with the biggest star counts are not libraries you import. Hermes Agent's README describes "the self-improving AI agent built by Nous Research" with a terminal interface and a gateway that connects it to Telegram, Discord, Slack, WhatsApp and Signal. OpenClaw's README describes itself as "an open-source AI assistant that runs on your own computer" and meets you in chat channels. Both ship installers, and both are products you run, in the way a self-hosted application is a product.

That matters for the comparison in two ways. First, a product that a person can install and talk to on their phone will attract stars from people who will never write a line of code against it, so its star count and a developer library's star count are measuring different audiences. That is my reading, not something the data proves. Second, the "used" test in my rubric undercounts Hermes Agent: its README's quick install is a shell script, so PyPI downloads (255,561 last month) miss most installs. I left the mechanical verdict as "ready with caveats" and told you why, rather than adjust the rubric to flatter it.

One practical finding from the pull: the PyPI package hermes-agent was at 0.19.0, uploaded 20 July 2026, while the GitHub stable releases were at v0.23.2 on 16 November. If you install from the registry you are four minor versions behind the repository. Which channel you pin to is a decision to make on purpose. I tested Hermes Agent's memory and skills limits on an earlier version, and the results are in my Hermes Agent memory and skills post. For the head-to-head between the two products, see OpenClaw vs Hermes Agent, and for running the OpenClaw side on your own server see my OpenClaw self-hosting guide.

8. Project by project

Each note below states the measured facts, the verdict, and what the number does not tell you.

LangGraph: ready

45,155 stars, MIT licence, release 1.2.23 on 19 November, 274 commits in 90 days, and 60,983,685 downloads last month, the most in the set and 1,351 per star. Its package description is "Building stateful, multi-actor applications with LLMs". Open issues and PRs are 1.1 percent of stars. A download figure this large probably includes packages that depend on it, which I did not trace, so treat it as reach.

OpenAI Agents SDK: ready

30,766 stars, MIT licence, release 0.25.0 on 18 November, 458 commits, 20,211,362 downloads. The 0.x version number signals that the maintainers have not declared a stable 1.0 API, and I did not read the changelog to see how often interfaces break. Whether it works well with models from other providers is a question for its documentation, which I did not test.

Google ADK: ready

22,272 stars, Apache-2.0, release 2.14.1 on 12 November, 1,462 commits, 11,026,606 downloads. The repository is google/adk-python. The data says nothing about how tightly it ties you to Google Cloud, and I did not test that.

PydanticAI: ready

21,288 stars, MIT licence, release 2.71.0 on 19 November, 2,910 commits (the highest among the libraries), 6,964,997 downloads. It also carries the highest open-issue ratio among the ready group, 8.6 percent of stars.

CrewAI: ready

61,100 stars, MIT licence, release 1.15.43 on 19 November, 465 commits, 2,578,165 downloads. It passes every test. Its stars-to-downloads ratio (42 downloads per star) is the weakest of the ready libraries, which is the stars-versus-usage gap from section 6.

OpenClaw: ready by the rubric

394,804 stars, MIT licence, release 2026.10.33 on 18 November, about 49,000 commits in 90 days, 12,515,567 npm downloads, 8,445 open issues and PRs (2.1 percent of stars). It passes mechanically. Remember it is an assistant you run, not a library, and the npm figure is not comparable to a PyPI figure.

Hermes Agent: ready with caveats

264,649 stars, MIT licence, stable release v0.23.2 on 16 November, about 50,000 commits in 90 days, 53,889 open issues and PRs (20.4 percent of stars), 255,561 PyPI downloads. The caveat that fails the rubric is the download count, which undercounts script installs. The caveat I would add is the registry lagging the repository by four minor versions.

Letta Code: ready with caveats

3,875 stars, Apache-2.0, release 0.34.66 on 19 November, 1,029 commits, 346,143 npm downloads. It is the current Letta project, so judge Letta by this repository and not the 25,489-star one. It fails only the 1,000,000-download bar.

AG2: ready with caveats

5,076 stars, Apache-2.0, release 1.3.2 on 15 November, 326 commits, 225,944 downloads. It is actively maintained and small. I did not read its governance or its relationship to AutoGen, so I make no claim about either.

smolagents: ready with caveats

30,444 stars, Apache-2.0, last release 1.26.0 on 29 May 2026 (174 days old), 23 commits in 90 days, 745,500 downloads. The repository was last pushed on 18 November, so it is not abandoned, but release and commit activity are low next to the others. Its PyPI description calls it "a barebones library for agents" where agents write Python code to call tools.

AutoGen: not yet, avoid for new projects

61,936 stars, but the README says archived and unmaintained, the newest release is 415 days old, and there were 3 commits in 90 days. Existing users have a documented migration path to Microsoft Agent Framework. Its 432,006 monthly downloads are real, and they show how many existing projects still depend on it.

Letta, original repository: not yet, avoid for new projects

25,489 stars, newest release 0.16.8 on 14 May 2026, 5 commits in 90 days, and a README that retires the V1 server. Use Letta Code instead.

Microsoft Agent Framework: unscored

I could not read the repository, so I cannot score it. The registry says agent-framework-core 1.26.0 was uploaded on 12 November 2026 and had 1,644,297 downloads last month, and the agent-framework meta-package had 194,722. That is real adoption. It is not the same evidence as commit and release history, so I left the verdict empty. Check the repository from your own network before relying on it.

9. How the verdicts move if you change the rubric

Every threshold in section 3 is a choice, so I checked which choices carry the result.

  • Lower the download bar to 200,000. Hermes Agent (255,561), Letta Code (346,143) and AG2 (225,944) all become "ready". Everything that is maintained would then be ready. The 1,000,000 line is what splits the groups, and I picked it, so treat "ready with caveats" for those three as "smaller user base" and nothing harsher.
  • Relax the release bar to 180 days. smolagents (174 days) would pass the release test but still fail the 50-commits test with 23 commits. It stays "ready with caveats".
  • The AutoGen and Letta verdicts do not move. They rest on the projects' own README statements and on release ages above a year or near half a year with almost no commits. No reasonable threshold changes them.
  • The six "ready" verdicts do not move under any bar I tried: each has a release within 7 days, at least 274 commits in 90 days and at least 2,578,165 downloads.

That is the useful result. The top and the bottom of this list are stable, and the middle is a judgment about how much user base you need.

11. Rerun it

This is the collection script, trimmed to the parts that matter. It prints JSON for each repository. GitHub allows 60 unauthenticated requests an hour and this makes three per repository, so keep the list under about 18 repositories or set a token.

import json, re, time, datetime as dt, urllib.request

REPOS = [("LangGraph", "langchain-ai/langgraph", "pypi:langgraph"),
         ("PydanticAI", "pydantic/pydantic-ai", "pypi:pydantic-ai"),
         ("OpenClaw", "openclaw/openclaw", "npm:openclaw")]  # add the rest
NOW = dt.datetime.now(dt.timezone.utc)

def get(url, headers=False):
    req = urllib.request.Request(url, headers={"User-Agent": "scorecard/1.0",
                                               "Accept": "application/vnd.github+json"})
    with urllib.request.urlopen(req, timeout=25) as r:
        body = json.loads(r.read().decode())
        return (body, dict(r.headers)) if headers else body

def days_since(s):
    return (NOW - dt.datetime.fromisoformat(s.replace("Z", "+00:00"))).days

since90 = (NOW - dt.timedelta(days=90)).strftime("%Y-%m-%dT%H:%M:%SZ")
for name, repo, pkg in REPOS:
    r = get(f"https://api.github.com/repos/{repo}")
    rels = [x for x in get(f"https://api.github.com/repos/{repo}/releases?per_page=100")
            if not x["draft"] and not x["prerelease"]]
    _, h = get(f"https://api.github.com/repos/{repo}/commits?since={since90}&per_page=1", True)
    m = re.search(r'[?&]page=(\d+)>; rel="last"', h.get("Link", ""))
    kind, pname = pkg.split(":")
    if kind == "pypi":
        dl = get(f"https://pypistats.org/api/packages/{pname}/recent")["data"]["last_month"]
        time.sleep(1.5)
    else:
        dl = get(f"https://api.npmjs.org/downloads/point/last-month/{pname}")["downloads"]
    print(json.dumps({"name": name, "stars": r["stargazers_count"],
        "release_age_days": days_since(rels[0]["published_at"]) if rels else None,
        "commits_90d": int(m.group(1)) if m else None, "downloads": dl}))

And the rubric, exactly as I applied it. I tested it against all twelve rows above and it reproduces every verdict in the table.

def verdict(release_age_days, commits_90d, downloads, documented_unmaintained=False):
    commits = commits_90d or 0
    if documented_unmaintained or (release_age_days is not None and release_age_days > 365):
        return "not yet / avoid for new projects"
    maintained = release_age_days is not None and release_age_days <= 90 and commits >= 50
    used = (downloads or 0) >= 1_000_000
    if maintained and used:
        return "ready"
    if maintained or (release_age_days is not None and release_age_days <= 365 and commits > 0):
        return "ready-with-caveats"
    return "not yet / avoid for new projects"

The documented_unmaintained flag is the one thing you must set by hand, from reading each README. No API field carries it, and it is the field that caught AutoGen and the original Letta repository. I would rerun this quarterly, because every figure here is a snapshot and the release ages move daily.

12. What I did not measure

  • I did not build the same task in any framework. Nothing here speaks to API quality, debugging experience, or how well each one handles tool errors, state or concurrency.
  • I did not read source code, changelogs, security advisories or licences beyond the SPDX field GitHub reports.
  • I could not read the Microsoft Agent Framework repository, so I have no commit, star or issue data for it.
  • Download counts include CI runs, mirrors and dependents. I did not trace dependents, and PyPI and npm figures are not the same unit.
  • I did not check star history, so I cannot say whether any star count was inflated. I only showed that stars and usage diverge.
  • The 90-day commit totals for OpenClaw and Hermes Agent are GitHub's pagination counts. I sampled 100 commits from each but did not reconcile the totals commit by commit.
  • The rubric thresholds (90 days, 50 commits, 1,000,000 downloads) are my choices. Section 9 shows where they matter.
  • Everything is a single snapshot taken between 13:01 and 13:05 UTC on 19 November 2026.

Frequently Asked Questions

What is the best AI agent framework in 2026?

It depends on your stack, but on maintenance and adoption evidence from 19 November 2026, LangGraph, OpenAI Agents SDK, Google ADK, PydanticAI and CrewAI all passed a rubric requiring a stable release in the last 90 days, at least 50 commits in 90 days and at least 1,000,000 monthly downloads. I did not build the same task in each, so this ranks maintenance and adoption, not developer experience.

Are GitHub stars a good way to choose an agent framework?

No. On 19 November 2026, downloads per star ranged from 7 for AutoGen to 1,351 for LangGraph among the projects with a comparable figure, a 193-fold spread. CrewAI has about 1.35 times LangGraph's stars and about 4 percent of its monthly downloads. Stars measure attention, and the original Letta repository still carries about 6.6 times the stars of the repository now being developed.

Is AutoGen still maintained?

Its own README says the project is archived and no longer maintained, with no bug fixes or security fixes from Microsoft. On 19 November 2026 its newest release was 415 days old and it had 3 commits in 90 days. GitHub's archived flag still read false, so the README and the API field disagree. The README points new users to Microsoft Agent Framework and links a migration guide.

Is Microsoft Agent Framework a safe choice?

I could not score it. The repository address that AutoGen's README and the PyPI metadata link to returned 404 to my unauthenticated requests on 19 November 2026, so I had no commit or release history. The registry showed agent-framework-core 1.26.0 uploaded on 12 November 2026 with 1,644,297 downloads in the last month. Check the repository from your own network before you commit to it.

Are Hermes Agent and OpenClaw agent frameworks?

Their own READMEs describe them as assistants you run yourself, with chat-channel gateways and installers, rather than libraries you import into a product. Their star counts (264,649 and 394,804 on 19 November 2026) mostly reflect a different audience than a developer library's. Compare them on hosting model, channels and release channel, not on stars.
