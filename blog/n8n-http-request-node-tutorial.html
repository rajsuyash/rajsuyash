N8N HTTP Request Node Tutorial: Connect Any API (2026)

The HTTP Request node is n8n's universal connector. If a service has an API, you can reach it. This tutorial covers the settings, and the two places people get caught: what pagination returns and what retries actually retry.

The n8n HTTP Request node sends a request to any URL and returns the response as workflow data. Set the method and URL, choose an authentication credential, add headers, query parameters or a body, and turn on Pagination when the API returns results in pages. Use it when n8n has no dedicated node for the service.

The six steps below are: a first GET request, authentication, a JSON POST body, pagination, parsing the output, and error handling. If you are still getting started with n8n, read how to build your first n8n workflow first. For Google Sheets specifically, use the Google Sheets integration guide, because a dedicated node is less work than hand-built requests.

Step 1: Add the HTTP Request Node to Your Workflow

In the n8n canvas, click the plus button, search for "HTTP Request" and select it. The panel has these main parameters:

  • Method: DELETE, GET, HEAD, OPTIONS, PATCH, POST or PUT (plus PROPFIND, MKCOL, MOVE, COPY and REPORT once you turn on Enable WebDAV Methods in Options)
  • URL: the full endpoint URL
  • Authentication: a predefined credential type, or a generic one (Step 3)
  • Send Query Parameters: the URL query string, as name/value fields or as JSON
  • Send Headers: custom request headers, as name/value fields or as JSON
  • Send Body: the request body for POST, PUT and PATCH (Step 4)
  • Options (Add Option): Array Format in Query Parameters, Batching, Ignore SSL Issues, Lowercase Headers, Redirects, Response, Pagination, Proxy, Timeout and Enable WebDAV Methods

Retry settings are not in Options. They are on the node's Settings tab (Step 6).

Tip: most API documentation shows a curl command. In the node's Parameters tab, select Import cURL, paste the command and select Import. n8n fills in the method, URL, headers and body, and overwrites whatever was configured before. The import always brings values in as strings, so if an API needs numbers or booleans, switch Using Fields Below to Using JSON and paste a JSON object instead.

Step 2: Make Your First GET Request

This example reads exchange rates from a public endpoint that needs no key. The pattern is common: fetch data from an external source on a schedule, then route it into a spreadsheet or database.

  1. Set Method to GET
  2. Set URL to https://open.er-api.com/v6/latest/USD
  3. Leave Authentication as "None"
  4. Select "Execute node"

The output panel shows the parsed JSON. In later nodes, {{ $json.rates.EUR }} reads the euro rate. I made the same request with curl on 27 November 2026: it returned result: success, base_code: USD, a last-update time of Fri, 27 Nov 2026 00:02:31 +0000, and rates.EUR of 0.911313. Your number will differ because the rate changes daily.

Step 3: Add Authentication

Most production APIs need credentials. n8n recommends Predefined Credential Type whenever n8n has a credential for the service, because it is the easiest to set up and manage. It also lets the HTTP Request node reuse the credential you created for a built-in node, so you can call an endpoint that node does not expose. For everything else, choose Generic Credential Type:

Generic auth type When to use How to configure in n8n
Header Auth An API key or token sent in a custom header, such as X-API-Key Create a Header Auth credential. Set the header Name and its Value.
Bearer Auth APIs that expect Authorization: Bearer <token> Create a Bearer Auth credential and paste the token only. The node adds the Bearer prefix itself.
Basic Auth APIs that take a username and password, or an application password Create a Basic Auth credential with the username and password.
Digest Auth APIs that require HTTP digest authentication Create a Digest Auth credential with the username and password.
Query Auth One key passed as a query parameter Create a Query Auth credential with the parameter name and value.
Custom Auth Several headers, query parameters or body fields at once Create a Custom Auth credential holding JSON with headers, qs, body or a mix.
Simplified Custom Auth The same as Custom Auth, with the secrets kept out of the template (n8n 2.35.0 and later) Write a JSON template with {{placeholder}} markers. The form then shows one field per placeholder.
OAuth1 API APIs that still require OAuth1 signing Enter the authorization, access token and request token URLs, the consumer key and secret, and a signature method.
OAuth2 API Google APIs, Salesforce and most modern SaaS platforms Choose a grant type (Authorization Code, Client Credentials or PKCE), then enter the URLs, client ID and secret the provider gave you.

To add one, pick the method under Authentication, then select "Create new credential". The credential lives apart from the workflow. The example 01 download below references its credential by name only and contains no token. The expensive mistake is the reverse: pasting the token into a header parameter works identically, so n8n shows no warning, and the secret then sits in every export and backup. Example 01, node C, shows exactly that.

A Bearer Token Call You Can Reproduce

Set Authentication to Generic Credential Type, choose Bearer Auth, create a credential with the token demo-token-value, and set the URL to https://httpbin.org/bearer. httpbin echoes what it received. I made the same call with curl on 27 November 2026 and got {"authenticated": true, "token": "demo-token-value"}. Remove the credential and the call returns 401, which is the quickest way to learn what a failed auth looks like in the output.

Step 4: Send a POST Request with a JSON Body

POST requests send data to an API, usually to create or update a record. In the HTTP Request node:

  1. Set Method to POST
  2. Turn on Send Body
  3. Choose a Body Content Type: Form URLencoded, Form-Data, JSON, n8n Binary File or Raw
  4. For JSON, either enter name/value pairs (Using Fields Below) or a whole object (Using JSON)

If you put an expression inside the JSON field, wrap the entire object in double curly brackets, for example:

{{ { "orderId": $json.orderId, "amountCents": $json.amountCents } }}

Without the outer brackets n8n reports "JSON parameter needs to be valid JSON". Use Form URLencoded for APIs that expect application/x-www-form-urlencoded. For file uploads use Form-Data and set the parameter type to n8n Binary File. The n8n Binary File body type sends the file as the whole request body with no multipart wrapper, so an API that only accepts multipart answers 415 Unsupported Media Type.

I posted {"orderId": "ORD-10042", "amountCents": 4900} to https://httpbin.org/post with curl on 27 November 2026. The echo showed the JSON body unchanged and a Content-Type of application/json, which is what a correctly configured JSON body should send.

Step 5: Handle Pagination

Many APIs return results in pages. Without pagination, your workflow gets the first page and silently misses the rest. In the HTTP Request node, select Add Option and then Pagination. There are three decisions to make.

1. How does the next request differ?

Pagination mode When to use How it works
Update a Parameter in Each Request The API takes a page number, offset or cursor that you can compute Add one or more parameters, each with a Type (Query, Header or Body), a Name and a Value expression. Every Name and Value must be filled in: the node refuses to run with an empty value, because that would loop forever.
Response Contains Next URL The API returns the full URL of the next page Set Next URL to an expression such as {{ $response.body.next }}. The node requests that URL on each loop.

Three built-in variables are available in these expressions: $pageCount (how many pages have been fetched, starting at 0), $request, and $response with .body, .headers and .statusCode. Because $pageCount starts at zero, a one-based page parameter uses {{ $pageCount + 1 }} and an offset of 50 per page uses {{ $pageCount * 50 }}.

2. When is pagination complete?

Pagination Complete When Stops when Watch out for
Response Is Empty (default) The response body is an empty array or has no body It never fires on a JSON object. A last page of {"items": []} is an object, so the node keeps requesting.
Receive Specific Status Code(s) The response status is in your comma-separated list, such as 404 Only useful for APIs that signal the end with a status code.
Other Your expression evaluates to true, such as {{ $response.body.next === null }} The expression reads the current response, not the next one. In this mode a non-2xx response raises an error unless Never Error is on.

3. How do you stop a runaway loop?

Turn on Limit Pages Fetched and set Max Pages, and use Interval Between Requests (ms) to space the calls. If the completion condition is wrong, the node also has a backstop: after the response repeats identically, it stops with "The returned response was identical 5x, so requests got stopped". Do not rely on the backstop. Set the cap.

What the node returns

This is the part the older version of this page got wrong. A paginating node does not merge the pages into one array. The node emits one item per page when the API wraps its list in an object, and one item per element only when the response body is a top-level JSON array. Most APIs wrap their lists. Add a Split Out node after the HTTP Request node, put the list field name in Fields To Split Out, and you get one item per record.

I ran the parameters from example 02 against both public APIs on 27 November 2026, using a re-implementation of the pagination loop:

dummyjson: requests=3 output_items=3 products_in_items=150 skips=0,50,100 total=194
pokeapi:   requests=3 output_items=3 results_in_items=60 count=1351

Local server, last page is {"items": []}, Complete When = Response Is Empty:
requests before the node gave up = 6
error: The returned response was identical 5x, so requests got stopped

Three requests gave three items, with 150 and 60 records inside them. Example 02 below now reports pages and records separately.

Step 6: Parse and Use the Response Data

When the response is JSON, n8n parses it for you (the Response option defaults to Autodetect). Reference fields with expressions in any later node:

  • {{ $json.id }}: a top-level field named "id"
  • {{ $json.customer.email }}: a nested field
  • {{ $json.items[0].name }}: the first element of an array
  • {{ $json.items.length }}: the number of elements in an array

If the list sits inside an object, use Split Out to turn it into one item per record. To process items in groups, or to pause between groups, use Loop Over Items (named Split in Batches in older tutorials). Older tutorials also mention the Item Lists node, which is hidden from the node picker in n8n@2.49.8. To rename fields or build new ones, use Edit Fields (Set).

The Response option changes what the node outputs:

  • Include Response Headers and Status: returns the status code and headers next to the body. Needed when your logic depends on the status.
  • Never Error: treats every status code as success, so a 429 or 500 arrives as data instead of failing the node.
  • Response Format: Autodetect (default), File, JSON or Text.

Five Workflow Patterns Built on the HTTP Request Node

These are design sketches. I did not run these five, and I give no time-saving figures for them. Each one names the node settings that matter.

1. Enrich a CRM contact

Trigger on a new contact with the CRM's own node. Call an enrichment API with a GET, passing the email through Send Query Parameters rather than building the URL by hand, so special characters are encoded for you. Write the returned fields back with the CRM node. Check the provider's current docs first: enrichment products change owners and endpoints.

2. Post to a service with no node

For a Discord webhook or a Mastodon instance, send a POST with a JSON body. Trigger it from an RSS feed or a spreadsheet row. Keep the token in a credential, not in the header parameters.

3. Hand an order to a logistics API

On a new order, POST the order details as JSON and store the ID the logistics provider returns. Because a retried POST can create the order twice, send an idempotency key derived from the order, not from the attempt. Example 04 below shows the difference, and the error handling guide goes further.

4. Watch a price or status endpoint

Run a Schedule Trigger, GET the endpoint, compare the value with a stored baseline (for example in Airtable, using the n8n Airtable integration) and send an alert on a change. Check the site's terms before scraping anything that is not an API.

5. Fetch, summarize and send a report

Pull data from an analytics API, send it to a model API with a second HTTP Request node, and email the result through a mail API. Watch two things: pagination on the first call (Step 5) and rate limits on the second (the 429 section below).

Using the HTTP Request Node as an AI Agent Tool

You can attach the HTTP Request node to an n8n AI agent as a tool. When it is attached as a tool, an Optimize Response option appears. It is off until you turn it on. It trims the response before the model sees it, which can reduce token cost and help the model ignore unimportant detail. You choose the expected response type:

  • JSON: name the field that holds the data, then include all fields, selected fields or all but some fields
  • HTML: pick a CSS selector, optionally strip tags and omit elements, and optionally truncate
  • Text: optionally truncate

The truncation limit for HTML and Text defaults to 1,000 characters, so check it before you trust a long page to arrive whole. For the wider picture of agent builds, see the AI agents page.

Common Errors and How to Fix Them

Most of these are in the n8n documentation for the node. Pair this section with the n8n error handling guide before you run anything in production.

  • 400 Bad Request: a query parameter has an invalid name or value, or an array in a query parameter is formatted the wrong way. Try the Array Format in Query Parameters option (No Brackets, Brackets Only, or Brackets with Indices) and check the API's docs.
  • 401 or 403: authentication or permissions. Check the credential, the header name, and whether the key has the scope for this endpoint. n8n words the 403 as "Forbidden - perhaps check your credentials".
  • 404, "The resource you are requesting could not be found": the URL is wrong or the API version is deprecated.
  • JSON parameter needs to be valid JSON: a missing quote or comma, or an expression whose JSON is not wrapped in double curly brackets.
  • ECONNREFUSED on a local service: inside a Docker container, localhost is the container itself. Use host.docker.internal (on Linux, add --add-host=host.docker.internal:host-gateway) or the Compose service name. On Node.js 17 and later, localhost can resolve to IPv6 first, so use 127.0.0.1.
  • SSL certificate error: turn on Ignore SSL Issues in Options, only for services you trust.
  • Uploaded file arrives with the wrong name: with Form-Data, the file name comes from the binary data, not from the Name field. Set it in the Convert to File node or a Code node first.

429 Too Many Requests

n8n gives you three tools, and they do different jobs:

  • Batching (Add Option, then Batching): set Items per Batch and a Batch Interval in milliseconds. Each input item is its own request, so this spaces them out. It is the cheapest way to avoid the 429 in the first place.
  • Retry On Fail (node Settings tab): set Max Tries (at most 5) and Wait Between Tries (at most 5,000 ms). The HTTP Request node does not read the API's Retry-After header.
  • Loop Over Items plus Wait: for rate limits that need longer pauses than 5 seconds.

Retry On Fail has one rule that catches people. n8n retries a node when the node fails, or when the first output item carries an error property. With Never Error on, a 429 is not a failure: it is data. The node succeeds and nothing is retried. I ran that against a local server that answers 429, 429, then 200:

Never Error on  + Retry On Fail (max 3): server hits=1, item statusCode=429
Never Error off + Retry On Fail (max 3): server hits=3, final item={"ok":true}
Error only in the 2nd output item:       node ran 1 time (only the first item is checked)

So pick one approach per node. Either let the node fail and use Retry On Fail, or turn Never Error on and branch on the status code yourself. Example 03 below does the second. The retries, rate limits and queue mode guide covers the first in more depth.

When to Use the HTTP Request Node vs. a Built-In Integration

Situation Use Built-In Node Use HTTP Request Node
Common create, read and update operations Yes, faster setup Not needed
An endpoint the built-in node does not expose No Yes, with Predefined Credential Type to reuse the node's credential
A service with no n8n integration at all No Yes
Your own internal API No Yes
First-time OAuth2 sign-in Yes, the built-in node handles the flow More setup: you supply the URLs and client details
Fetching many records Check the node for a Return All option first Yes, when you need control over the paging scheme (Step 5)

Frequently Asked Questions

What is the N8N HTTP Request node used for?

It sends an HTTP request (DELETE, GET, HEAD, OPTIONS, PATCH, POST or PUT) to any URL and returns the response as workflow data. You set the URL, method, authentication, headers, query parameters and body in the node. Use it for services that have no dedicated n8n node, for endpoints a built-in node does not expose, and for internal APIs.

How do I add authentication to the N8N HTTP Request node?

Open the Authentication dropdown. Choose Predefined Credential Type when n8n already has a credential for the service. Otherwise choose Generic Credential Type and pick Basic, Bearer, Custom, Digest, Header, OAuth1, OAuth2, Query or Simplified Custom Auth (Simplified Custom Auth needs n8n 2.35.0 or later). Credentials are stored outside the workflow, so an exported workflow does not contain the secret.

Can the N8N HTTP Request node handle paginated API responses?

Yes. Under Options, add Pagination and choose Update a Parameter in Each Request or Response Contains Next URL. Then set when pagination is complete: Response Is Empty, Receive Specific Status Code(s), or Other with an expression. Set Limit Pages Fetched so a wrong condition cannot loop forever.

Why does a paginated HTTP Request node return one item per page instead of one item per record?

When the API wraps its list in an object, such as {"products": [...]}, each page becomes one item. The node only splits into one item per element when the response body is a top-level JSON array. Add a Split Out node after the HTTP Request node and name the list field to get one item per record.

How do I handle a 429 Too Many Requests error in the HTTP Request node?

Use the Batching option (Items per Batch and Batch Interval) to space requests out, turn on Retry On Fail in the node Settings (at most 5 tries, at most 5 seconds apart), or combine Loop Over Items with a Wait node for longer delays. Retry On Fail only fires when the node fails, so leave Never Error off on a node you want retried.

When should I use the HTTP Request node instead of a built-in n8n integration?

Use a built-in node for common operations on a service it covers, because it handles field mapping and the sign-in flow. Use the HTTP Request node when no node exists for the service, when the node does not expose the endpoint you need, or when you are calling your own API. You can reuse a built-in node's credential in the HTTP Request node with Predefined Credential Type.
