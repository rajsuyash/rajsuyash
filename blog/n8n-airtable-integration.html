Airtable n8n Integration: Setup Guide and Real Workflows

Connect Airtable to n8n in about ten minutes, with no code. This guide covers authentication, every operation the node supports, and five real business workflows.

n8n connects to Airtable through a built-in Airtable node, so there is nothing to install. You authenticate with an Airtable Personal Access Token (or OAuth2), pick a base and table from dropdowns, and the node gives you five operations: append a record, list records, read one record by ID, update a record, and delete a record. A separate Airtable Trigger node polls your base on a schedule and fires a workflow when something new appears. Setup takes about ten minutes. Everything below is the detail: token scopes, each operation, five workflows worth building, and the errors you will hit.

This guide now uses the Airtable Trigger node instead of a hand-rolled Schedule Trigger poll, corrects the API rate limit (5 requests per second per base on every plan, not just Free), fixes a broken filter formula example, and updates n8n and Zapier pricing.

Why Connect N8N to Airtable?

Airtable is a good database that does not act on its own data. Records sit still until someone touches them. That is the gap n8n fills.

Connected, you can:

  • Automatically add form submissions to Airtable without a Zapier middleman
  • Send Slack alerts when a record reaches a specific status
  • Sync Airtable data to Google Sheets for weekly reporting
  • Route new Airtable leads directly into HubSpot or your CRM
  • Generate and email invoices from Airtable project records

Every one of those replaces a person remembering to do something. That is the whole value: Airtable stops being a place data sits and starts being a place data moves through. Our n8n automation practice builds these for clients, but the basic ones are genuinely a weekend job.

What You Need Before You Start

  • An N8N instance (cloud or self-hosted). See Build Your First N8N Workflow if you need setup help.
  • An Airtable account (free tier works fine for this tutorial)
  • An Airtable base with at least one table and a few records

No developer experience needed. The node handles the API calls.

Step 1: Generate an Airtable Personal Access Token

Airtable fully deprecated API keys in February 2024. You need a Personal Access Token (PAT). n8n also supports OAuth2 for Airtable, but a PAT is simpler for a single workspace and is what n8n recommends.

  1. Log in to Airtable and go to airtable.com/create/tokens
  2. Click Create token
  3. Give it a name (e.g., "N8N Integration")
  4. Under Scopes, add the following:
    • data.records:read
    • data.records:write
    • schema.bases:read
  5. Under Access, choose which bases this token can access. Select the base you want to automate, or choose "All bases" if you plan to use multiple.
  6. Click Create token and copy it immediately. Airtable only shows it once.

Store it somewhere secure. You paste it into n8n next.

Step 2: Add Airtable Credentials to N8N

  1. Open your N8N instance and go to Settings > Credentials
  2. Click Add Credential and search for "Airtable"
  3. Select Airtable Personal Access Token API
  4. Paste your token into the Access Token field
  5. Click Save and then Test Connection to verify it works

Once the test passes, every Airtable node in your instance can use this credential.

Step 3: Understand the N8N Airtable Node Operations

The n8n Airtable node supports exactly five operations. Anything beyond them (upserts, schema changes, attachment handling) needs the HTTP Request node pointed at the Airtable API, reusing the same credential. Here is when to use each one:

Operation What It Does Common Use Case
List Returns multiple records from a table Pull all open leads, active projects, or pending tasks
Read Returns a single record by its Airtable Record ID Fetch one specific record to update or process it
Create (documented as "Append") Adds a new record to a table Log a new form submission, lead, or order
Update Modifies fields on an existing record Change a record's status, assign an owner, mark as complete
Delete Removes a record permanently Clean up test data or archive expired records

Most workflows combine two: List records in status "New Lead", then Update each to "Contacted" after sending an email.

Step 4: Build Your First N8N Airtable Workflow

A concrete example: log new webhook submissions to Airtable.

This assumes a Typeform or similar form posting to an n8n webhook (see the n8n webhook tutorial).

Workflow: Log Form Submissions to Airtable

  1. Add a Webhook trigger node. Set method to POST and copy the webhook URL.
  2. Add an Airtable node. Select your credential, choose Create operation.
  3. In the Airtable node, select your Base and Table from the dropdowns.
  4. Map the incoming webhook fields to your Airtable columns:
    • Name: {{ $json.name }}
    • Email: {{ $json.email }}
    • Message: {{ $json.message }}
    • Submitted At: {{ $now }}
  5. Click Execute Node to test with a sample submission.
  6. Activate the workflow.

Step 5: Read and Filter Airtable Records

The List operation is powerful when combined with N8N's filtering and branching tools.

Detecting New Records: Use the Airtable Trigger Node

You do not need to hand-roll a polling loop. n8n ships an Airtable Trigger node that watches a base and emits a New Airtable event. Its Poll Times setting offers Every Minute, Every Hour, Every Day and Every Week. It is polling rather than a push webhook, so one minute is the floor on detection delay. If you need true real-time, Airtable's own webhooks API can post to an n8n Webhook node instead.

How to Filter Records in the Airtable Node

When using the List operation, you can apply an Airtable filter formula in the Filter by Formula field. This is standard Airtable formula syntax:

  • Status = "Open" returns only records where Status is Open
  • AND(Status = "Active", DATETIME_DIFF(TODAY(), {Last Contact}, 'days') > 7) for records that are active and have not been contacted in 7 days
  • NOT({Email} = "") returns records where Email is not blank

Filtering at the Airtable level keeps the workflow efficient: fewer records pulled, fewer nodes, faster execution, and fewer requests against the rate limit.

The List operation also sorts by any field and accepts a record limit. For large tables, set a limit of 50 to 100 and page through with n8n's pagination options.

Step 6: Update Records Automatically

The detail that trips people up: Update needs the Airtable Record ID.

A List or Read node upstream returns each record with an id field. Set the Update node's ID field to {{ $json.id }} from that output.

Example: Update Lead Status After Sending Email

  1. List node: pull records where Status = "New Lead"
  2. Gmail node: send a personalized outreach email using the record's Name and Email fields
  3. Airtable Update node: set Status to "Contacted" and Last Contact to {{ $now }}

Five Real Business Workflows Using N8N and Airtable

Patterns we have built for clients:

1. New Customer Onboarding Tracker

A form submission creates an Airtable record, sends a welcome email, and opens a task in the project tool. The record becomes the single source of truth for onboarding status.

2. Invoice Generation from Project Records

Every Monday, list records where Project Status = "Completed" and Invoice Sent is empty. For each, generate a PDF invoice, email it, and write the invoice date back.

3. Lead Routing from Airtable to CRM

Every 15 minutes, list records where Lead Source = "Website" and CRM Synced = false, create the HubSpot contact, then set CRM Synced = true. No double entry, no missed leads.

4. Weekly Status Report from Airtable to Slack

Every Friday at 4 PM, pull all project records, group by status, post a formatted summary to Slack. Leadership gets visibility without anyone exporting anything.

5. Inventory Alert System

Each morning, read inventory records and compare Quantity against Reorder Threshold. Below it, send an alert and draft a purchase order. The team reorders before stock runs out.

Common Issues and How to Fix Them

Error: "Authentication failed"

Your Personal Access Token may have expired or lacks the required scopes. Generate a new token and ensure you have included data.records:read, data.records:write, and schema.bases:read. Re-enter it in N8N's credential settings.

Error: "Table not found"

The table name in your N8N node must match the Airtable table name exactly, including capitalization. Do not use the table ID format unless N8N specifically asks for it.

Records not updating

Check that you are passing the correct Record ID. Use an N8N Set node to explicitly extract {{ $json.id }} from your List/Read output before passing it to the Update node.

Hitting Airtable's API rate limits

Airtable allows 5 requests per second per base, and 50 requests per second across all traffic using a single personal access token. Those limits are identical on every plan, paid ones included. Exceed them and Airtable returns a 429 and refuses further requests for 30 seconds. If your workflow processes many records at once, add a Wait node between batches (200ms is safe). Upgrading your Airtable plan will not raise this ceiling.

Frequently Asked Questions

Does N8N have a native Airtable integration?

Yes. N8N includes a built-in Airtable node that supports all major operations: listing records, reading a record by ID, creating records, updating records, and deleting records. You only need an Airtable Personal Access Token to authenticate.

What can I automate between N8N and Airtable?

Common N8N-Airtable automations include: syncing form submissions to Airtable, sending Slack alerts when new Airtable records are created, generating invoices from Airtable data, routing leads from Airtable to your CRM, and scheduling reports from Airtable to email or Google Sheets.

Is N8N free to use with Airtable?

N8N offers a free self-hosted version with no workflow limits. The cloud-hosted plan starts at $20/month and includes a generous free tier. Airtable's free plan supports up to 1,000 records per base and is enough for most small business automations.

How do I trigger an N8N workflow when an Airtable record changes?

Airtable does not natively push webhooks on record changes. The standard approach in N8N is to use a Schedule Trigger node that polls your Airtable base at regular intervals (e.g., every 5 minutes), then uses an IF node to check whether any records have been updated since the last run.

Can N8N connect Airtable to other apps automatically?

Yes. N8N supports over 400 integrations. You can connect Airtable to Gmail, Slack, HubSpot, Google Sheets, Notion, Typeform, and dozens of other tools in a single automated workflow. No code required.
